# Leading Cryptographic Inventory & PQC Analysis Tools

Modern cryptographic discovery platforms integrate multiple data sources (code, networks, systems) into a unified inventory for risk scoring. For example, NIST’s draft architecture depicts a workflow where *code repositories*, *network traffic*, and *system assets* feed into a normalization engine, which then produces a prioritized cryptographic bill of materials (CBOM) for risk assessment. The tools below represent current market leaders, each using different scanning methods (static code analysis, endpoint agents, or passive network sensors) to identify algorithms, keys, certificates and libraries. For each, we summarize the solution approach, key design elements, and known weaknesses or limitations cited by analysts and users.

## IBM Quantum Safe Explorer & Advisor  
IBM’s suite uses **static and dynamic analysis** to build a comprehensive CBOM. The *Quantum Safe Explorer* performs deep static scanning of source code and binaries to find cryptographic APIs, hardcoded keys, and vulnerable algorithms. Concurrently, *Quantum Safe Advisor* monitors runtime environments (TLS configurations, certificates, key usage, etc.) to contextualize the inventory and flag any in-use weak crypto. A *Remediator* tool then helps deploy post-quantum or hybrid schemes (e.g. proxy encryption) without rewriting legacy code. IBM also contributed the CycloneDX CBOM standard and open-sourced a CBOMkit to encourage ecosystem adoption.

- **Strengths:** Broad language and binary support enables inventory across diverse apps; risk-ranking links crypto instances to business context. Standardized CBOM output (CycloneDX) allows integration with DevSecOps/SBOM tools. Built-in guidance for hybrid/PQC migration accelerates replacement of weak crypto with minimal disruption.
- **Limitations:** Static analysis only covers supported languages/libraries; crypto loaded at runtime or in config files may be missed. Full coverage requires scanning all codebases and environments, which is resource-intensive. The suite highlights issues but doesn’t auto-remediate them – human experts must implement algorithm upgrades or proxy configs.

## Keyfactor Crypto-Agility (InfoSec Global AgileSec)  
Keyfactor’s platform (formerly InfoSec Global AgileSec) is **endpoint-centric**. It deploys lightweight agents (or reuses existing EDR agents like CrowdStrike/Tanium) on servers and desktops to scan for crypto artifacts. Each host’s file system, registry, memory and processes are checked for TLS certificates, SSH keys, crypto libraries, and usage patterns. The system correlates found items with their services (e.g. linking a private key file to the app using it) and ingests network/cloud telemetry for context. Discovered assets and associated risks (weak algorithms, expired certs, policy violations) are aggregated in a centralized dashboard with continuous monitoring and compliance checks.

- **Strengths:** Deep visibility into “hidden” crypto on each host (e.g. outdated OpenSSL libraries or 1024-bit keys in keystores). Easy deployment when existing EDR/agent infrastructure is available. Provides consolidated risk reports and policy alerts (NIST, PCI-DSS, internal) with real-time compliance monitoring.
- **Limitations:** Requires an agent or sensor on every machine; legacy systems, embedded devices or OT equipment that can’t run agents become blind spots. Focused on IT endpoints – it doesn’t analyze pure network-only devices or deeply embedded IoT without additional tooling. Host scans reveal *that* crypto artifacts exist on a system, but may not automatically show *how* they’re invoked in custom code (static code analysis would still be needed).

## SandboxAQ AQtive Guard  
AQtive Guard (from SandboxAQ, ex-Cryptosense) uses a **multi-layer approach**. It combines three concurrent analysers: a **passive network tap** that observes live traffic for TLS/VPN protocols and cipher suites; an **application runtime hook** that logs all crypto library calls within running processes; and a **filesystem/binary scanner** that examines executables and files for keys and crypto functions. By correlating these sources, AQtive can, for instance, link a TLS 1.0 session seen on the wire to the specific app and key on disk that generated it. A unified dashboard then highlights any policy violations (e.g. banned algorithms) and provides cross-layer insights.

- **Strengths:** Comprehensive coverage (“crypto in code, on disk, and on the wire”) catches issues static-only or network-only tools miss. Runtime analyzer can detect dynamically generated keys and legacy cipher calls invisible to static scans. Integrated policy enforcement flags FIPS-140 or PCI-DSS violations across network and apps. Proven scalability: used in large enterprises and government (e.g. U.S. Air Force, HHS).
- **Limitations:** Deployment is complex due to multi-pronged setup. Instrumenting live applications may introduce overhead or stability risks; many customers run the application analyzer only in test environments. The network tap requires access to traffic (SPAN ports), which can be difficult in some infrastructures. Handling large volumes of data from three sources needs mature analytics to avoid missing signals. It’s a premium solution best suited to organizations willing to invest in full crypto visibility.

## CryptoNext COMPASS  
COMPASS (by CryptoNext Security) is a **passive network probe** focused on cryptography. A dedicated high-speed sensor is placed on key network segments (SPANS/TAPs) to sniff all traffic. It automatically decodes 100+ IT/OT protocols, extracting crypto details (algorithms, key lengths, certificate fields) from each handshake. Findings are sent to an analytics platform, where inventory, flagging of weak cipher usage, and correlation with other data sources (certificate managers, endpoint scans) take place. All discovered crypto assets are reported in CBOM format for consistency.

- **Strengths:** Fully passive and non-intrusive – it never generates traffic or touches endpoints. Ideal for sensitive environments (industrial, healthcare) where active scans are not possible. Very broad protocol support (HTTPS, SSH, VPN, ICS/IoT protocols, etc.) – can catch, e.g., outdated ciphers on SCADA links or forgotten unencrypted channels. Outputs focused crypto findings (instead of raw packets) to reduce noise. Easily scalable: one probe covers ~1 Gbps (higher speeds planned) and findings export via API in standard CBOM format.
- **Limitations:** As a *network-only* tool, it sees **only** in-transit crypto. At-rest encryption (file vaults, encrypted databases, local files) is invisible. It cannot decrypt sessions (unless keys are provided), so proprietary or SSL-in-SSL traffic can be missed. Highly distributed or cloud networks may need many probes for full coverage. Its value depends on correlation with other data sources; without integrations, gaps will remain.

## Quantum Xchange CipherInsights  
CipherInsights (now part of Keyfactor) is another **passive traffic monitoring** tool. It continually observes network flows (including internet egress) to detect cryptographic “risk factors”. For each session it checks things like use of quantum-vulnerable key exchange (RSA/ECC), weak cipher suites, plaintext where encryption is expected, or expired certificates. It offers a real-time dashboard of your crypto posture, showing what percentage of traffic is quantum-safe vs. legacy, and can even simulate how a system might fail when switching to PQC. Data is exported in CBOM and can feed into SIEMs or PKI management systems.

- **Strengths:** Continuous, real-time crypto posture monitoring with zero network impact (fully passive). Because it sees all observed traffic (including shadow IT), it can catch unexpected crypto use – e.g. an internal app suddenly calling an insecure external API. Focus on dozens of risk factors (expired certs, weak ciphers, missing encryption) yields actionable alerts rather than raw data. The built-in quantum-safe progress dashboard is useful for executives to track PQC readiness. Recognized by NIST NCCoE as a recommended discovery tool for PQC migration.
- **Limitations:** Network-only visibility – if it flags a weak cipher on port 443, you still must log into that server to fix it (though integration with Keyfactor’s certificate platform can help tie it together). Encrypted traffic within a tunnel (HTTPS inside VPN) will not be visible unless the probe is placed accordingly. High-throughput networks can generate very large event volumes, so sizing and data management must be planned. As CipherInsights is being merged into Keyfactor’s suite, its future standalone form may change, though its capabilities remain relevant.

## PQStation QVision  
QVision is an **AI-driven inventory platform**. It deploys lightweight sensors and integrates with existing security tools to collect data on cryptography across the enterprise. It catalogs SSL/TLS certificates, SSH keys, algorithms in configs or code, and exposed secrets. A correlation engine matches certificates to services, highlights weak key lengths, reused keys, and identifies exactly where a vulnerable cipher is used (which library or config). The platform includes continuous policy monitoring and produces compliance reports to translate raw data into executive metrics.

- **Strengths:** Flexible deployment: use dedicated sensors or tap into existing SIEM/EDR for broad coverage. Covers a wide scope (certs, keys, algorithm usage in code/config), with insight into relationships (e.g. which apps use weak ciphers in common libraries). Provides real-time alerts to keep new crypto risk in check. Strong compliance features with executive reporting.
- **Limitations:** A newer entrant with less proven track record. Integration breadth depends on what existing tools can supply; for example, appliances or closed systems may only be seen if they can run a sensor or export logs. The AI improves with more data, so very small or unique environments may get limited insights initially. It focuses on quantum risk, so it may lack some traditional crypto management capabilities (e.g. detailed certificate lifecycle functions).

## QryptoCyber Platform  
QryptoCyber is an AI-orchestrated CBOM solution built around **“Five Pillars”**: External Network, Internal Network, IT/OT Assets, Databases, and Code. Instead of developing its own scanner for each domain, QryptoCyber integrates best-of-breed tools and third-party feeds. For example, it may use external certificate scans and passive network monitoring for networks, endpoint agents or vulnerability data for assets, database config scans for DBs, and static code analysis for CI/CD pipelines. All findings funnel into QryptoCyber’s AI engine, which deduplicates and categorizes the crypto usage into a unified CBOM. The AI then prioritizes vulnerabilities and suggests a remediation roadmap.

- **Strengths:** Ultra-broad coverage – by addressing all five pillars, it avoids blind spots (databases or code often slip through other tools). Flexible deployment (“your agent or ours”) allows using existing scans and logs, reducing duplication. AI-driven analysis translates thousands of crypto findings into concise risk stories (e.g. “50 high-risk assets out of 1000 total”) and produces PQC readiness scores for stakeholders. It delivers a complete CBOM and a dynamic remediation plan, making it effectively an automated consulting process.
- **Limitations:** Its inventory accuracy depends on the quality of underlying data sources. If an environment lacks existing scanners or sensors, QryptoCyber must deploy its own collectors, which may be less mature than specialized tools. As a newer startup, some advanced features (e.g. automated database scanning, specialized OT protocol support) are still evolving. The AI recommendations are only as good as the input data – unusual or bespoke crypto use cases may still require expert review. Organizations should verify data handling policies (especially if using any cloud components) to ensure sensitive crypto material isn’t exposed.

## ISARA Advance  
ISARA Advance is a **telemetry-aggregating** platform (agentless). It taps into existing network and endpoint data feeds (NDR/EDR, TLS logs, etc.) to collect cryptography information. For example, it may ingest TLS handshake logs from a network sensor and certificate inventories from an endpoint tool. Advance then consolidates this data into a central inventory of crypto in motion and at rest, flagging vulnerable or misconfigured uses. The dashboard highlights “bad usage” (e.g. deprecated algorithms, policy violations) and offers quantum risk scoring.

- **Strengths:** Agentless design allows rapid deployment: it simply uses data you already have, with no new scanning load on systems. Focuses on quantum vulnerabilities across all crypto primitives (encryption, signatures, key exchange, hashing). Strong compliance support for internal/external standards. Backed by ISARA’s PQC expertise, paving the way from inventory to actual quantum-safe implementation.
- **Limitations:** Relies entirely on existing telemetry: if your NDR/EDR or logs are sparse, Advance’s inventory will be incomplete. It provides high-level inventory rather than deep technical detail – it won’t trace a finding to the exact code line. OT or custom systems that don’t feed into your central logs are invisible. In short, gaps in monitoring equal gaps in inventory.

## Tychon ACDI (Automated Cryptographic Discovery & Inventory)  
Tychon (commonly used in U.S. government) includes a **PQC readiness module**. An agent or scripted query runs on each managed Windows/Linux endpoint to scan for crypto artifacts. It enumerates certificates, keys (including “soft certs”), crypto libraries and versions, and checks active connections (open TLS/SSL sockets) on the host. Tychon then creates an inventory aligned with federal mandates (NSM-10, HR 7535).

- **Strengths:** Designed for compliance – built-in queries and dashboards map directly to U.S. government crypto inventory requirements. Continuously updates the inventory after the baseline scan. Endpoint-depth can discover things network-only tools miss (e.g. file-based encryption by local apps). Familiar interface for agencies already using Tychon, with potential remediation actions from the same console.
- **Limitations:** Geared primarily for standard server/desktop OSes; it does *not* analyze custom application source code or watch network traffic beyond that host’s own activity. Limited to identifying known crypto components on each endpoint – it may not trace those components to their calling process. Not applicable to OT/embedded systems (PLCs, industrial devices). Mostly aligned with U.S. government standards, so its scope and user base tend to be federal/defense customers.

## AppViewX AVX ONE PQC Assessment Tool  
AppViewX’s AVX ONE platform introduced a **PQC assessment** tool in 2025. It statically analyzes application **code repositories** and binary dependencies, inventories certificates and keys, and checks config files for insecure crypto settings. The tool generates a CBOM and a composite “PQC readiness” score, and provides step-by-step remediation guidance. It can emit reports in CycloneDX or CSV and integrates into CI/CD pipelines (e.g. GitHub Actions, AWS CodeBuild) to catch issues in builds.

- **Strengths:** Broad scope across code, infrastructure, and identity: it covers custom codebases, network configurations, and certificate stores in one tool. Outputs are highly actionable (PQC score, prioritized fixes, CBOM deliverable) which aids both developers and executives. The CI/CD integrations allow preventive checks, so policy violations are caught before production. Dashboards cater to both technical teams and management.
- **Limitations:** Still a new product; features may evolve with user feedback. Its static code analysis yields most value when organizations have substantial in-house code – companies relying mainly on COTS software will gain less. It does *not* perform any active or runtime/network discovery, so crypto in black-box appliances will only be found via certificates. The CI/CD features assume mature DevOps practices; organizations without automated builds see limited benefit.

## Open-Source and DIY Approaches  
In addition to commercial tools, a variety of open-source frameworks can be combined for cryptographic discovery and PQC assessment. Examples include IBM’s **CBOMkit** (with Hyperion for code and Theia for containers), CodeQL or SonarQube custom rules for static crypto scanning, and Zeek scripts or Wireshark for network cipher analysis. These are often coordinated via the CycloneDX 1.6 CBOM standard for merging outputs.

- **Strengths:** No licensing cost and high flexibility – security teams can customize scanners and rules to their exact environments. Open standards (CycloneDX SBOM/CBOM) let you merge disparate tools into a unified inventory. Good for sensitive or air-gapped environments where cloud-based services are not allowed, or for proof-of-concept pilots.
- **Limitations:** DIY solutions impose heavy setup and maintenance burdens. Static analysis tools often require writing and tuning custom detection rules for each language and library, and accuracy can lag behind commercial products. Support is community-driven, so if a tool has a bug or lacks a feature, you are on your own. There are no out-of-the-box risk scoring engines or compliance dashboards – teams typically must build those around the data themselves.

**Summary:** Each of the above platforms excels in certain areas and brings unique architecture designs to the cryptographic discovery problem. Common challenges include ensuring full coverage (code vs. network vs. devices), handling legacy or closed systems, and balancing deployment complexity versus visibility. No single tool is perfect: for example, network-only probes cannot see on-disk crypto, while agent-based scanners may miss OSes without agents. Understanding these trade-offs is key to planning a full ECDAT solution.
